# Modes & Agents

## Built-in Modes

| Mode         | Description                             | Modifies Files | Runs Commands |
| ------------ | --------------------------------------- | -------------- | ------------- |
| **Code**     | Full autonomous coding agent            | ✓              | ✓             |
| **Ask**      | Answer questions, no modifications      | ✗              | ✗             |
| **Plan**     | Create and execute task plans           | ✓              | ✓             |
| **Advanced** | Orchestrator with subtask decomposition | ✓              | ✓             |

### Code Mode (Default)

The agent can read files, write files, search code, and run terminal commands. It acts autonomously to complete tasks, asking for tool approval as configured.

### Ask Mode

Read-only mode. The agent can read files and search for context but will not modify anything. Use this for:

- Understanding code
- Getting explanations
- Architecture discussions
- Code review (read-only)

### Plan Mode

Activates the orchestrator to decompose the task into numbered steps:

1. **Decomposition** — LLM breaks the task into subtasks
2. **Execution** — Each subtask is executed sequentially
3. **Summary** — Final summary of all changes made

Use `/plan` or switch to Plan mode before sending your message.

### Advanced Mode

Full orchestrator mode with multi-pass execution, including:

- Task complexity classification
- Subtask mode assignment (each step can be code/ask/plan)
- Verification passes after changes
- Final summary generation

## Switching Modes

- **Mode selector** — dropdown in the chat panel header
- **Slash commands** — `/plan`, `/ask`, `/code`, `/advanced`
- **Programmatic** — mode engine API in `@opencob/core`

## Custom Modes

Define custom modes in `.opencob/custom_modes.json`:

```json
[
  {
    "name": "security-audit",
    "roleDefinition": "You are a security auditor specializing in OWASP Top 10 vulnerabilities. You analyze code for security issues and suggest fixes.",
    "customInstructions": "Focus on: injection, broken auth, sensitive data exposure, XXE, broken access control. Rate each finding as Critical/High/Medium/Low.",
    "groups": ["read"]
  },
  {
    "name": "docs-writer",
    "roleDefinition": "You are a technical writer who creates clear, concise documentation.",
    "customInstructions": "Write documentation in Markdown. Include code examples. Target audience: intermediate developers.",
    "groups": ["read", "write"]
  }
]
```

### Mode Groups

Groups control which tool categories the mode can access:

| Group     | Tools included                                                 |
| --------- | -------------------------------------------------------------- |
| `read`    | read_file, search_files, list_directory, list_code_definitions |
| `write`   | write_to_file, apply_diff, insert_content                      |
| `command` | execute_command                                                |
| `browser` | browser_action                                                 |
| `mcp`     | MCP server tools                                               |

## Custom Agents

Agents (in `.opencob/agents/`) are like modes but with additional structure:

```markdown
---
name: architect
description: System architect for high-level design discussions
tools: [read_file, search_files, list_directory]
---

You are a senior software architect. You help with:

- System design decisions
- Technology selection
- Architecture documentation
- Trade-off analysis

You do NOT write implementation code. Instead, you provide:

- Architecture Decision Records (ADRs)
- Component diagrams (Mermaid)
- Interface contracts
- Migration strategies
```

Key differences from modes:

- Agents have an explicit `tools` allowlist (whitelist)
- Agents carry a full persona in their markdown body
- Agents appear in the mode selector dropdown
- Multiple agents can coexist; only one mode is active

## Mode Rules

Define rules that apply to specific modes in `.opencob/rules/`:

```markdown
---
mode: code
---

When in code mode:

- Always run tests after making changes
- Use apply_diff for small changes, write_to_file for new files
- Read the file before modifying it
```
